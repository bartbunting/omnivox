# Omnivox 1.16.0 candidate checks

This is functional acceptance for palette-aware character feedback, not an
acoustic latency or listening measurement. The negotiated `emacsvox_letter`
command applies the registered palette voice and actual fallback tuning while
preserving character rate, cancellation and the host capital-pitch policy.
See the [protocol](../protocols/presentation-timeline.md#palette-aware-isolated-characters).

## Source and integration

The candidate merges the published release line ending at `e7e7ab6` into `main`,
which previously remained at `b43d893` plus character fix `3ccea52`. Published
1.12–1.15 changes and their changelog history are retained. The separate dirty
`feat/orca-backend` checkout is not a release input and remains unchanged.

Integration preserves the 1.14 capital-pitch decision: the actual fallback
engine selects the configured absolute cue or off setting. An enabled cue also
supplies pitch context to native planning; otherwise an explicit native pitch
could replace it. The native-boundary regression first failed without that
context, then passed with it. Lowercase and off retain ordinary native tuning.

## Windows qualification

The full guarded Windows development staging passed with build identity
`3f8ce8ff46d85767`. Its first attempt
compiled the server but failed when companion packaging queried Git inside Docker:
the separate worktree's common Git directory was outside the source mount. A
read-only mount of that Git directory makes the same guarded target work with
this worktree. No source, toolchain or release guard was bypassed for this repair.
The acceptance runtime is separate from the live Emacsvox installation.

Native configuration checks passed. Fresh compiled Emacsvox completed lowercase,
uppercase and apostrophe feedback with the requested Max voice on both lanes.
The burst completed its first and last requests and cancelled the ten intervening
requests, each with one terminal callback. Native Flite, RuTTS and TGSpeechBox
staging smoke checks also passed; Piper remains a release-CI qualification.

The first direct-executable client attempt omitted the staged eSpeak data path
and fell back to WinRT. After exporting that path through WSLENV, the test still
used Linux's slash-separated exact voice identity. The retained Windows harness
changes only its checkout path and that identity to `espeak:gmw\en+max`.
With these platform-specific test inputs corrected, all assertions passed;
no production source or expected routing behavior was weakened.
