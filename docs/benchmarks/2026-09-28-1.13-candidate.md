# Omnivox 1.13.0 candidate checks

Pre-release functional checks on 2026-09-28. These results do not establish
publication or audible acceptance. The candidate's production source is
`dd6ed9ea46e4603f79e896e80953a56ae094e1d3`; subsequent commits `d97a7f0` and
`7327b18` change test portability and documentation only.

## Results

- Linux: the pinned, locked workspace tests passed (1,099 passing test-result
  entries, including a nested subprocess test; two ignored). Workspace/all-target
  Clippy with the CLI Piper feature passed. The supported `make build` payload
  reports 1.13.0; external registration and all seven input-check methods passed.
- Windows x64: the native CI payload passed the full registration scenario when
  run through WSL. With candidate and temporary files on the Windows filesystem,
  input checks passed, with two Unix-only methods skipped. The expanded cases
  cover 15,001 ms, one hour and the largest unsigned 32-bit silence request.
- Both Macs: native registration passed exact voice listing, WAV synthesis,
  preview, tracked speech, shared settings, independent workers, frozen inputs,
  fresh activation, blocked startup transmission and retirement. Six input-check
  methods passed; the memory-limited method failed before Omnivox started because
  its process setup was not portable. Commit `7327b18` confines this method to
  Linux and checks huge silence requests separately on all platforms. The final
  tag workflow must verify that correction on both Macs before publication.
- The preliminary runs passed the other native build, test and companion jobs.
  Documentation, formatting and package-contract checks also passed locally.

The [first platform run](https://github.com/bartbunting/omnivox/actions/runs/36365129105)
found a fixture assertion that mistook macOS's `/private` directory for leaked
settings. The [second run](https://github.com/bartbunting/omnivox/actions/runs/36365483091)
passed registration after the assertion was narrowed to the actual private
inputs, and exposed the memory-limit setup failure described above. Neither
preliminary run is an all-green release result.

## Local build and test limits

An isolated long build path failed while compiling Piper's eSpeak data. A new,
shorter build root completed without a production-code change. Original failed
logs remain alongside the successful logs. A Windows WAV test also timed out
when executable/data/output were accessed through the WSL filesystem share;
the repeat using Windows-local files passed. This is not a qualification of
Windows operation from WSL network paths.

No installed Windows runtime was replaced. No physical listening sign-off was
collected. The fixtures use test-generated PCM or null output and do not qualify
an independently supplied proprietary runtime, voice quality or audio-device
latency. Linux platform CI uses Ubuntu 24.04; local Linux checks ran under WSL.
