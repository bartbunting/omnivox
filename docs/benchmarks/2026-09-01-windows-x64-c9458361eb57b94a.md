# Windows x64 Development Latency Baseline, 2026-09-01

This is post-v1.5.1 development evidence, not a measurement of the published
v1.5.1 release artifact. The server still reported version `1.5.1`, but its
Omnivox source commit is 36 commits after the `v1.5.1` tag.

## Scope and provenance

- Target: `x86_64-pc-windows-gnu`, run through Windows interoperability from
  WSL2 on `Linux-6.18.33.2-microsoft-standard-WSL2-x86_64-with-glibc2.43`.
- Server build ID: `c9458361eb57b94a`.
- Server Omnivox commit: `7f2f332a3bf23909e78c9a42124609998331b91f`.
- Emacsvox deployment commit:
  `cd15e34adbf67e4f3ad80395aefb47df1d33ac1f`.
- Benchmark harness commit: `4762d4a`.
- Toolchain: Rust `1.97.1`, Python `3.14.4`, and MinGW GCC `12-win32`.
- Engines: WinRT, eSpeak NG, RHVoice, Flite with compiled SLT, DECtalk, and
  Eloquence.
- Runtime provenance: DECtalk used the bundled pinned archive; RHVoice and
  Eloquence used external, user-supplied runtimes. The raw reports retain the
  observed runtime and build hashes.

The payload labels itself `local-dirty-worktree` because untracked local files
were present. Its recorded tracked-worktree hashes are empty-diff hashes for
both Omnivox and Emacsvox. It is therefore useful development evidence, but it
is not represented as a clean reproducible release build.

## Method

`tools/benchmark_server.py` ran 20 recorded iterations for each of six cases:
character, word, line, dense-action timeline, multipart timeline, and rapid
keyed replacement. Each engine has cold and warm groups, for 240 recorded
winner samples per engine and 1,440 in total. Cold mode started a server for
every sample. Warm mode reused one server process and ran two unrecorded
warmups before each case.

The replacement case sent a burst of five dispatches. Every recorded sample
observed four stale dispatches cancelled and one winner completed. All 1,440
winners completed through the expected engine, with no fallback-engine
contamination. DECtalk and Eloquence were selected through the public runtime
routing policy; the harness configured no fallback engine and enforced the
expected engine ID.

Measurements use Python's `time.perf_counter_ns`. Dispatch-to-source ends when
the client receives the first `utterance_started` mixer-source marker, and
terminal timing ends when it receives the tracked terminal record. These are
protocol and mixer measurements, not physical acoustic onset measurements.
The raw reports use nearest-rank percentiles; with 20 samples, p99 is the
maximum observed value.

## Results

Warm dispatch-to-source p50, in milliseconds:

| Engine | Character | Word | Line | Dense | Multipart | Replacement |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| WinRT | 69.886 | 69.644 | 89.702 | 99.620 | 79.949 | 129.609 |
| eSpeak NG | 19.709 | 29.618 | 39.765 | 39.796 | 29.866 | 69.711 |
| RHVoice | 28.922 | 29.671 | 89.689 | 149.440 | 109.701 | 189.711 |
| Flite SLT | 29.508 | 29.836 | 79.903 | 119.295 | 79.779 | 149.693 |
| DECtalk | 69.788 | 69.635 | 79.545 | 79.751 | 79.663 | 109.889 |
| Eloquence | 19.777 | 19.681 | 29.941 | 49.587 | 39.597 | 79.635 |

Cold p50 ranges across all six cases and replacement cancellation p95, in
milliseconds:

| Engine | Process start to source p50 range | Dispatch to source p50 range | Cold cancel p95 | Warm cancel p95 |
| --- | ---: | ---: | ---: | ---: |
| WinRT | 1007.996–1215.524 | 112.945–170.468 | 0.537 | 0.703 |
| eSpeak NG | 845.567–1015.412 | 19.293–81.725 | 0.556 | 0.525 |
| RHVoice | 947.975–1127.797 | 97.190–267.463 | 0.567 | 0.742 |
| Flite SLT | 855.174–995.651 | 25.542–159.059 | 0.488 | 0.486 |
| DECtalk | 945.650–1065.713 | 71.957–122.274 | 0.478 | 0.691 |
| Eloquence | 905.738–985.471 | 29.376–87.672 | 0.391 | 0.568 |

The warm results show eSpeak NG fastest overall, while Eloquence is fastest for
word and line and nearly tied for character. DECtalk is consistent and beats
WinRT for line, dense, and replacement medians. Flite and RHVoice are quick for
character and word input but scale more slowly for longer synthesis. Cold
process startup dominates at roughly 0.85–1.22 seconds, supporting persistent
warm server processes. Replacement cancellation p95 remains below 0.75 ms for
every engine.

RHVoice's cold character group contains a 528.038 ms dispatch-to-source p99
outlier. It is retained in the raw evidence and should be investigated or
compared with later runs rather than removed.

## Limitations

- The runs were sequential rather than randomized, so host drift can affect
  cross-engine comparisons.
- Twenty samples characterize this development machine but are not enough for
  a broad platform claim.
- The reports preserve the selected engine ID but not the exact physical voice
  ID carried by the protocol marker. A future harness revision should retain
  `actual_voice` before comparing voice-specific results.
- This records mixer-source consumption, not device or acoustic onset, speech
  quality, intelligibility, working set, or long-session stability.
- External RHVoice and Eloquence installation details cannot be reproduced
  from these files alone, although the available runtime hashes are retained.
