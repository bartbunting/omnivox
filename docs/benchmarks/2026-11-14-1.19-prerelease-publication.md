# Omnivox 1.19 testing prerelease publication

[Omnivox v1.19.0-pre.2](https://github.com/bartbunting/omnivox/releases/tag/v1.19.0-pre.2)
was published on 2026-11-14 at 00:42:43 UTC as a testing prerelease. Its annotated, unsigned tag
identifies `0a043be2d6e67a90e2e1292863ac4abee32ad1ad`; its tag object is
`d73352a4da3d68d5535208b33d5c0d880d0047e4`. The matching Emacsvox candidate is
[`a751af1506b73b8a37a37085eb7a356a318da8ca`](https://github.com/bartbunting/emacsvox/commit/a751af1506b73b8a37a37085eb7a356a318da8ca),
available on `feat/macos-audio-devices`. This is not a separate Emacsvox release.

All 74 jobs in the
[tagged workflow](https://github.com/bartbunting/omnivox/actions/runs/43533121144)
passed on its first attempt. The exact public asset set contains 31 archives,
one Debian package and `sha256sums.txt`. All 33 GitHub asset digests match the
downloaded manifest, including its own calculated digest. The release is marked
prerelease and excluded from Latest; the Latest API still identifies `v1.18.0`.
The separate Homebrew testing channel is published as recorded below.

## Verification and corrected CI prerequisites

Local Linux verification used Rust 1.97.1: locked workspace tests reported 1,232
passes, no failures and two ignored tests across 38 result groups, including
subprocess test output. Locked workspace/all-target Clippy and formatting passed.
The first test invocation lacked prepared native companion sources; after the
normal preparation targets ran, the complete workspace invocation passed. Release
packaging/version/asset tests, documentation and paired Emacsvox links passed.

Candidate runs exposed three Windows CI compatibility issues, fixed before the
tag:

- [43523917997](https://github.com/bartbunting/omnivox/actions/runs/43523917997)
  failed a pipe-security test because Windows serialized the administrator SID as
  `LA`. The test now canonicalizes the independently expected SDDL through the
  native API. Restricted-token denial and noninheritance checks remain in place;
  runtime permissions did not change.
- [43525010077](https://github.com/bartbunting/omnivox/actions/runs/43525010077)
  exposed stale CMake target files after a runner image update, and a new MSVC
  preprocessor rejecting the pinned eSpeak headers' `__has_include_next` probe.
  Native target cache keys now include `ImageVersion`.
- [43526054821](https://github.com/bartbunting/omnivox/actions/runs/43526054821)
  showed that selecting MSVC's traditional preprocessor was insufficient. That
  attempted override was removed. The final build force-includes
  `tools/msvc-compat.h` on MSVC, defining the unavailable probe as false and using
  the upstream headers' existing Windows fallback. Dependency versions and
  sources remain unchanged by this compatibility fix.

The two intermediate runs were cancelled after their concrete failures were
captured and superseding source was prepared. The final
[candidate run](https://github.com/bartbunting/omnivox/actions/runs/43526908275)
passed 29 of 30 jobs. Its Windows ARM64 build compiled successfully but timed out
after ten seconds starting the Eloquence bridge. This intermittent gate failure
also occurred in [1.18.0 publication](2026-10-16-1.18-publication.md). Both the `pre.1` and `pre.2`
tagged release runs passed that bridge startup check without changing its source
or timeout. The underlying intermittent startup delay remains unresolved.

Native compilation, tests and WAV synthesis establish executable and packaging
coverage. Physical macOS device Apply, hotplug/reconnect, default-output changes,
Bluetooth/sleep and audible Emacs acceptance remain tester checks. The ignored
hardware smoke test is not counted as a successful device check.

## First draft and corrected package filename

Tag `v1.19.0-pre.1` remains at `081344ae815fdb56b61372bbcb53b033aaa8fae4`
(tag object `70f4263169b5f9a859b9d3464ae660e2258cf866`). Its
[full release run](https://github.com/bartbunting/omnivox/actions/runs/43528421449)
passed all 38 build-stage jobs and packaging. Draft creation uploaded all 33
assets, then the exact-name check rejected the Debian asset: GitHub changed
`omnivox_1.19.0~pre.1-1_amd64.deb` to
`omnivox_1.19.0.pre.1-1_amd64.deb`. A draft asset PATCH with the intended name
returned the same normalized name. Neither operation changed the file's digest.
The first draft remains unpublished and is labelled as an unpublished packaging
candidate; its tag and changelog section were not rewritten.

The correction uses `omnivox_1.19.0-pre.2-1_amd64.deb` as the download name and
retains `1.19.0~pre.2-1` in Debian metadata. A real `dpkg-deb` regression fixture
confirms that the filename does not change the package's version or ordering
before `1.19.0-1`. All 36 packaging/version/archive tests passed (16 Debian,
7 archive, 4 version, 5 asset-set and 4 TGSpeechBox), as did formatting,
documentation, paired documentation and locked metadata for all 16 workspace
packages. The first fixture run exposed this workstation's restrictive umask;
the fixture now sets Debian's required control-directory mode explicitly.
The correction changes no speech runtime code or external dependency version.

## Homebrew

[Tap PR 8](https://github.com/bartbunting/homebrew-omnivox/pull/8) adds the separate
keg-only `omnivox-pre` formula at `565549ee08c076992d81f7c4e52c0f510a30a7c0`.
Both native [Homebrew checks](https://github.com/bartbunting/homebrew-omnivox/actions/runs/43536546214)
passed on that exact final head. They cover formula style/audit, installation,
voice discovery and eSpeak/native/TGSpeechBox WAV synthesis, reinstall, a temporary
packaging-revision upgrade and removal. Installing and removing the prerelease
preserved the ordinary stable command. All 14 updater tests passed.

The PR merged at 00:54:06 UTC as
`258746082517f5f1c8db7400e8f3343d1db29d9b`. A clean checkout of that merged commit
passed `python3 tools/update_formula.py 1.19.0-pre.2 --prerelease --check`, verifying
both downloaded Mac archives and the exact formula contents. The prerelease
formula matches the native-tested head; the stable formula is byte-for-byte
unchanged from `0bad18a8fe309bdb842d43bcea65dfde216b3918` and remains at `1.18.0`.

The [first tap run](https://github.com/bartbunting/homebrew-omnivox/actions/runs/43536177927)
installed stable and prerelease successfully on Apple Silicon, then rejected the
explicit version stanza as redundant with the URL-inferred version. The formula
now omits that stanza; the updater preserves inferred versions and still rejects
any inconsistent explicit override. The superseded run was cancelled after its
failure was retained. The same native workflow was dispatched explicitly on the
corrected final PR commit because its push did not start another run.
