# Omnivox 1.15.0 candidate checks

This candidate combines the streaming onset fix with punctuation configuration
and its local editing service. Straight, curly and modifier apostrophes are
named at `all` without a configuration file; `some` retains natural contractions.
The proposed `most` level, custom profiles and live configuration reload are
outside this release.

## Existing evidence

The [matched onset comparison](2026-09-28-streaming-onset-fix.md) reproduced
the old converter's loss and retained the onset in all 50 fixed Windows loopback
captures. It used controlled helper PCM and a build differing from 1.14.0 only
by the audio patch. The converter source in this candidate is unchanged from
that verified fix.

The [configuration report](2026-09-28-punctuation-configuration.md) and
[editor report](2026-09-28-punctuation-editor.md) retain parsing, source-offset,
snapshot compatibility, two-worker recovery, draft and graphical coverage.
Their original observations remain unchanged. The candidate adds regressions
for all four apostrophe forms with no overrides, older public configuration
versions, explicit preservation and actual helper requests at `some` and `all`.

## Final Linux and client checks

With pinned Rust 1.97.1 and locked dependencies on Linux x64 under WSL2:

- Workspace tests passed: 1,142 passed and two prerequisite tests ignored.
- Workspace/all-target Clippy passed with the CLI Piper feature and warnings denied.
- `make build` produced a 1.15.0 payload with generated eSpeak data and notices.
- The optimized payload passed configuration/editor, both-worker, reset,
  retained-recovery, blocked-startup retirement and input-validation checks.
- The compiled Emacsvox editor passed six tests against that payload. Its
  graphical test was skipped in batch; the earlier separate graphical suite
  passed all 38 checks with the same editor behavior.
- Emacs bytecode and generated documentation checks passed. Packaging guards,
  archive verification tests and release asset membership tests passed.

These checks use fixture speech or captured speech calls and do not establish
new listening acceptance.

## Windows qualification

`make windows-omnivox-dev` passed in the sibling Emacsvox checkout. It rebuilt
the complete development runtime, verified helper determinism, checked payload
hashes and completed its native engine smoke checks. Build
`6b22b22f62c6f7b7` reports version 1.15.0. This GNU development target omits
Piper; Piper-enabled Linux and Windows Clippy passed, while the release workflow
qualifies the packaged native Piper companions separately.

The native Windows configuration harness passed editor review/save, Unicode
and preservation overrides, stale-write rejection, unchanged unrelated settings,
both workers, frozen recovery and blocked-startup retirement. The compiled
Emacsvox editor also passed a round trip through the actual bundled WSL launcher
and that exact Windows executable, including a rejected stale save that retains
the draft. Saving did not restart speech.

The added editor probe initially supplied Linux paths to variables that require
native host paths, then assumed a drive path without Windows' extended-path
prefix. Both harness assumptions were corrected; the failed runs and probe
versions are retained. No application change was needed. Two earlier development
builds were deliberately interrupted while the apostrophe defaults were being
clarified; only the completed build above qualifies the final candidate.
