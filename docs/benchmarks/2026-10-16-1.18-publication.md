## Verification

The first attempt timed out after ten seconds starting the 32-bit Eloquence
bridge in the Windows ARM64 build. The bridge and startup test were unchanged
from 1.17.0, and the candidate CI run had passed. Retrying the failed jobs passed
without changing source, the tag or the gate. The intermittent startup timeout
remains unresolved; earlier releases recorded similar failures. Both the failure
log and final successful job records are retained.

Release gates passed for the native targets, supported companions, corresponding
sources, Debian installation, downloaded archives and final asset membership.
The [deployment guide](../../.github/DEPLOYMENT.md#what-ci-validates) defines their
scope. The [candidate report](2026-10-16-1.18-candidate.md) retains local Linux
build, test and relocated-archive checks.

Additional checks used the published Windows archives. All nine core and
companion ZIP checksums passed. Both core layouts, executable architectures,
notices and packaged Cargo.lock files matched the release. The x64 archive ran
from a path containing spaces, with an unrelated working directory and empty
configuration: eSpeak, Windows voices and TGSpeechBox each listed voices and
produced valid canonical and raw WAV files. Native helper startup checks passed.
Windows ARM64 execution is covered by CI, not by this local x64 run.

Both published corresponding-source archives passed checksums and identified the
release commit and Cargo.lock. TGSpeechBox provenance identified upstream commit
`25b0e1ae65fb87705f0870c724dc8c91f3abbeba` in the binary and source archives.
The source-input lock digest difference between Windows and Linux corresponds
to CRLF versus LF serialization.
